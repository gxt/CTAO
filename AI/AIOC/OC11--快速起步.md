## 1.1 5 分钟了解 OpenCode

### 一句话说清楚

**OpenCode 是一个在终端里运行的 AI 编程助手。**

你说一句话，它帮你：读懂项目、修改代码、执行命令、自动完成多步任务。

### Vibe Coding：动嘴不动手

最近有个概念很火：**Vibe Coding**。

核心思想：**改代码或写文章，动嘴就够了，不需要自己上手。**

| 传统方式 | Vibe Coding |
|---------|-------------|
| 打开 IDE → 找文件 → 定位代码 → 手动改 → 保存 → 测试 | 你说"帮我加个错误处理" → AI 改好 → 测试通过 → 完成 |
| 你是执行者 | 你是指挥官，AI 是执行者 |

### AI 编程工具的两大类型

**IDE 类**（Cursor、Windsurf、GitHub Copilot、Trae）：
- 图形界面，所见即所得
- AI 作为编辑器的"副驾驶"
- 你还是主要操作者，需要盯着屏幕

**TUI 类**（Claude Code、Codex CLI、OpenCode）：
- 终端原生，轻量快速
- AI 是主要执行者，你是指挥官
- 可以开多个任务并行，不用盯着屏幕
- 可编程、可自动化、可嵌入 CI/CD

**OpenCode 属于 TUI 类。**

### TUI 类工具对比

| 工具 | 模型 | 价格 | 优点 | 缺点 |
|------|------|------|------|------|
| Claude Code | Claude 4.5 系列 | $20/月 | Anthropic 官方出品，体验完善 | 绑定 Claude 模型，国内访问不便 |
| Codex CLI | GPT-5.2 | $20/月 | 云端异步执行，可并行多任务 | 绑定 GPT 系列，国内访问不便 |
| **OpenCode** | 75+ 模型自由切换 | 免费 | 开源、模型自由、支持国产模型 | - |

**程序员**：3 分钟改完 30 分钟的活

## 1.2b 装不上怎么办？

### 问题 1：command not found

**排查步骤**：
1. 确认重启了终端
2. 检查 OpenCode 装在哪了：`ls -la ~/.opencode/bin/opencode`
3. 手动添加到 PATH

```bash
# macOS/Linux (zsh)
echo 'export PATH="$HOME/.opencode/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

### 问题 2：网络错误 / 下载超时

**解决方案**：
- 换其他安装方式（npm、Homebrew 等）
- 需要代理的用户请看 1.3 网络配置

### 问题 3：GitHub API 限流

**解决方案**：等一小时后重试，或用其他安装方式

## 1.3 网络配置：代理与环境变量

### 先判断：你需要看这一课吗？

- **用智谱、DeepSeek、通义千问等国产模型**：可以跳过，直接去 1.4 连接模型
- **使用 Claude、GPT 等国际模型**：请继续阅读

### 核心概念

代理服务器是一个"中转站"。你的请求先发给代理，代理再转发给目标服务器。

OpenCode 通过**环境变量**读取代理配置：

- `HTTP_PROXY`：HTTP 请求的代理地址
- `HTTPS_PROXY`：HTTPS 请求的代理地址

### 跟我做

**第 1 步：确认代理信息**

需要知道：
1. 代理地址：通常是 `127.0.0.1`
2. 端口号：如 `7890`、`8080`

**第 2 步：设置环境变量（临时）**

```bash
# macOS / Linux
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
```

```powershell
# Windows PowerShell
$env:HTTP_PROXY = "http://127.0.0.1:7890"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
```

**第 3 步：写入配置文件（永久生效）**

```bash
# macOS / Linux (zsh)
nano ~/.zshrc
# 添加：
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
source ~/.zshrc
```

### 核心概念：什么是 API Key？

**API Key 是你访问 AI 服务的"身份凭证"**。

- AI 公司提供 AI 服务
- API Key 就是这个身份标识
- 它还用于计费

::: danger 保护好你的 Key
- **不要分享给别人**
- **不要提交到 GitHub**
- **不要截图发社交媒体**
:::

### 配置方式

**方式一：TUI 内用 /connect**

在 OpenCode 界面输入：`/connect`

**方式二：终端用 opencode auth login**

```bash
opencode auth login
```

### 查看已配置的提供商

```bash

```

1. 环境变量（如 `ANTHROPIC_API_KEY`）
2. auth.json 文件
3. 配置文件中的认证信息

## 1.5 自动更新

### 默认行为

OpenCode 启动时自动检查并下载更新，大部分用户不需要关心。

### 手动更新

```bash
opencode upgrade
```

### 配置自动更新

在 `opencode.json` 中：

```json
{
  "autoupdate": false
}
```

- `true`：自动下载更新（默认）
- `false`：不检查更新
- `"notify"`：通知有新版本，但不自动下载
