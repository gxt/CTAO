## 3.1 Plan vs Build

### 两种工作模式

OpenCode 有两种工作模式：**Plan（规划）** 和 **Build（执行）**。

| 模式 | 作用 | 触发条件 |
|------|------|----------|
| **Plan 模式** | AI 只思考不动手，给出方案 | 输入以 `规划` 开头，或按 Tab 切换 |
| **Build 模式** | AI 思考后直接执行 | 默认模式，或按 Tab 切换 |

### Plan 模式

**什么时候用**：
- 复杂任务需要先理清思路
- 不确定具体实现方案
- 需要 AI 提供多个选择

**使用方式**：
1. 在消息前加 `规划：` 前缀
2. 或在输入框按 `Tab` 切换到 Plan 模式

**特点**：
- AI 只输出计划，不实际操作
- 可以反复调整方案
- 确认后再切换到 Build 执行

### Build 模式

**什么时候用**：
- 简单任务直接执行
- 方案已经确定
- 需要快速看到结果

**特点**：
- AI 思考后直接操作
- 自动读写文件、执行命令
- 适合日常开发

### 模式切换

- 按 **Tab** 键在 Plan/Build 之间切换
- Plan 模式输入框显示 `规划：...`
- Build 模式显示正常的 `>`

## 3.2 认识 Agent

### 什么是 Agent

Agent（智能体）是专门处理特定任务的 AI 助手。OpenCode 内置了多个专业 Agent：

| Agent | 作用 |
|-------|------|
| @explore | 探索代码库，理解项目结构 |
| @task | 创建子任务处理复杂工作 |
| @edit | 精确编辑代码 |
| @grep | 搜索代码内容 |
| @glob | 搜索文件名 |

### 如何调用 Agent

在输入框使用 `@` 符号：

```
@explore 帮我了解这个项目的结构
```

### 主要 Agent 介绍

**@explore（代码探索）**
- 分析项目结构和代码
- 理解模块之间的关系
- 生成代码报告

**@task（任务分解）**
- 将复杂任务拆分成小步骤
- 创建任务清单
- 自动执行并跟踪进度

**@edit（代码编辑）**
- 精确修改代码
- 支持多文件批量修改
- 保持代码风格一致

## 3.3 项目初始化

### 为什么要初始化

让 AI 快速了解你的项目：
- 项目使用的语言和框架
- 代码结构和目录布局
- 依赖和配置信息
- 编码规范和约定

### 使用 /init 命令

```bash
/opencode
> /init
```

或者直接让 AI 初始化：

```
请帮我初始化项目，让你能更好地理解代码
```

### 初始化做什么

1. **扫描项目结构**：识别语言、框架
2. **分析配置文件**：读取 package.json、tsconfig.json 等
3. **生成项目摘要**：创建项目知识库
4. **设置上下文**：让后续对话更有针对性

### 初始化后的好处

- AI 更准确地理解你的代码
- 减少重复解释项目背景
- 更精准的代码建议
